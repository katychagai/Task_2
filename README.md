## Задание 2: API-тесты

### Автотесты для проверки API Stellar Burgers

### Реализованные сценарии

Созданы API-тесты, покрывающие следующие функциональности:

1. **Создание пользователя** (`test_create_user.py`)
   - Создание уникального пользователя
   - Создание пользователя, который уже зарегистрирован
   - Создание пользователя без обязательных полей (email, password, name)

2. **Авторизация пользователя** (`test_login_user.py`)
   - Логин под существующим пользователем
   - Логин с несуществующими учетными данными
   - Логин с неверными полями (email или password)

3. **Изменение данных пользователя** (`test_update_user.py`)
   - Изменение полей пользователя с авторизацией (email, name, password)
   - Изменение полей пользователя без авторизации

4. **Создание заказа** (`test_create_order.py`)
   - Создание заказа с авторизацией и ингредиентами
   - Создание заказа с авторизацией без ингредиентов
   - Создание заказа без авторизации
   - Создание заказа с неверным хешем ингредиентов

5. **Получение заказов пользователя** (`test_get_orders.py`)
   - Получение заказов авторизованного пользователя
   - Получение заказов неавторизованного пользователя

**Всего тестов:** 22 (21 успешных, 1 ожидаемый провал)

### Структура проекта

- `tests/` - пакет, содержащий тесты, разделенные по функциональности:
  - `test_create_user.py` - тесты создания пользователя
  - `test_login_user.py` - тесты авторизации
  - `test_update_user.py` - тесты обновления данных пользователя
  - `test_create_order.py` - тесты создания заказа
  - `test_get_orders.py` - тесты получения заказов
- `conftest.py` - фикстуры pytest для настройки тестов и очистки данных
- `helpers.py` - вспомогательные функции для генерации данных и работы с API
- `urls.py` - функции для работы с API endpoints
- `data.py` - константы (статус коды, сообщения об ошибках, тестовые данные)
- `config.py` - конфигурация проекта (базовый URL API)

### Запуск автотестов

**Установка зависимостей**

> `$ pip install -r requirements.txt`

**Запуск автотестов**

> `$ pytest tests/ -v`

**Запуск автотестов с генерацией Allure отчетов**

> `$ pytest tests/ -v --alluredir=allure_results`

**Просмотр Allure отчетов**

> `$ allure serve allure_results`

### Особенности реализации

- Использование фикстур pytest для изоляции тестов и автоматической очистки данных
- Генерация уникальных данных пользователя с использованием timestamp для предотвращения конфликтов
- Автоматическое обновление токенов при истечении срока действия
- Подробное логирование шагов тестов с использованием Allure
- Параметризация тестов для проверки различных полей и сценариев
